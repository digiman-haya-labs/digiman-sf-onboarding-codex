# Salesforce CLI をインストールする

ユーザーから明示的にインストールを依頼されたときにだけ、この手順を実行する。
依頼されていない段階でこの手順の内容を説明してはいけない。

## 実行前に伝えること

作業を始める前に、次の 2 点を 1〜2 文で伝える。

- これからインストールを実行すること
- ネットワーク接続とフォルダ外への書き込みが必要なため、途中で許可を求める確認が出ること
  （環境によっては、一度エラーになってから確認が出ることがある）

## 手順

### 1. 現状を確認する

```
command -v sf
```

見つかった場合はインストールを実行せず、導入済みであることを報告して終わる。

### 2. インストール方式を決める

**npm を第一候補にする。** Salesforce 公式が案内している方式で、
管理者権限なしに全 OS 共通で導入できる。

```
npm install @salesforce/cli --global
```

`npm` が使えない場合（`command not found: npm`）は、Node.js が未導入。
このとき、勝手に Node.js や Homebrew の導入を始めない。
Node.js を先に入れる必要があることを伝え、社内手順で導入するか
DigiMan 担当に連絡するかを選んでもらう。

npm が使えない環境で、それでも導入を進めたい場合は、
公式インストーラの配布ページを案内して手動導入に切り替える。

- 配布ページ: https://developer.salesforce.com/tools/salesforcecli
- macOS: `.pkg`（Apple Silicon 用と Intel 用がある）

> **Homebrew は使わない。**
> `salesforce-cli` の cask は Homebrew 側で deprecated（理由: `fails_gatekeeper_check`）とされ、
> 2026-09-01 に disable される。以降 `brew install --cask salesforce-cli` は失敗する。

なお、npm 版とインストーラ版を両方入れるとパスが競合する。
Salesforce 公式も「どちらか一方にすること」と案内している。どちらか 1 つだけにする。

### 3. 結果を確認する

```
command -v sf
```

見つからない場合は、成功したと報告しない。`sf --version` も叩かない。
見つかった場合だけ、続けてバージョンを確認する。

```
sf --version
```

新しくインストールしたコマンドが同じセッションで見つからないことがある。
その場合は、コマンドの置き場所をシェルがまだ読み込んでいない可能性を疑い、
ターミナルを開き直して、もう一度このフォルダで Codex を起動するよう案内する。

## 承認されなかったとき

インストールに必要な許可が下りなかった場合は、失敗として正しく報告する。
ただし、一度サンドボックスやネットワーク制限で失敗しただけの場合は、
まだ最終結果ではない。承認を求める表示が出ていないかを確認してもらう。

そのうえで、次の順で案内する。

1. このフォルダの `.codex/config.toml` の末尾にある 2 行
   （`[permissions.digiman-sf-onboarding.network]` と `enabled = true`）の行頭の `#` を消して保存し、
   Codex を起動し直してもらう。これでこのフォルダだけネットワークが使えるようになる。
   設定は起動時に一度だけ読み込まれるため、起動し直しが必要であることを 1 文で添える。
2. そのうえで、もう一度送ってもらう依頼文を 1 つ示す。

   ```text
   Salesforce CLI をインストールして
   ```

3. それでも進まない場合は、権限設定を自分で変えず DigiMan 担当に連絡してもらう。
   `/permissions` でも変更できるが、これは Codex 自体が受け取るコマンドでエージェントには届かない。
   案内する場合は、私宛の依頼ではないことと、どれを選ぶべきかは担当に確認することを添える。

## 失敗したときの切り分け

報告は「何が起きたか」「考えられる原因」「次に送る依頼文 1 つ」の順で短くまとめる。

- `EACCES` / `permission denied` — npm のグローバル領域への書き込み権限がない
- `command not found: npm` — Node.js が未導入
- ネットワーク関連のエラー — 承認が下りていないか、プロキシ環境の可能性
  この場合は上の「承認されなかったとき」に進む

原因が特定できないときは、推測で断定せず、エラー出力の該当行をそのまま示す。

## やってはいけないこと

- `sudo` を伴うコマンドを、何をするか伝えずに実行する
- 失敗しているのに成功したと報告する
- 依頼されていないのに設定ファイル（`~/.codex/config.toml` など）を書き換える
- インストールのついでに、依頼されていない組織認証（`sf org login`）まで進める
- Node.js や Homebrew の導入を、確認なしに始める

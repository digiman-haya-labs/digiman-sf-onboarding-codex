# Salesforce CLI Onboarding（Codex 版 / Windows）

このフォルダは `sf`（Salesforce CLI）の導入確認と質問回答専用のエージェントです。
OpenAI Codex を **Windows の PowerShell** で使うことを前提にしています。

> **うまくいかないときは**
> 画面に出ている文字をそのままコピーして、DigiMan の担当者までお送りください。
> ご自身でセキュリティや権限の設定を変える必要はありません。

## 必要なもの

- **Windows 11**（推奨）
  Windows 10 でも動く場合がありますが、最新の更新が適用された 1809 以降が実質の下限です。
- **64bit 版の Windows**（32bit では動きません）
- **`winget` が使えること**
  スタートメニューで「ターミナル」を開き `winget --version` で確認できます。
  使えない場合は Windows Update を先に済ませてください。
- **ChatGPT アカウント**（Plus 以上のプランで、CLI の利用が案内されています）

Node.js は**不要**です。Salesforce CLI をインストーラで入れる手順にしてあり、
Node.js はインストーラに同梱されています。

> **WSL2 は使いません。** Codex は Windows の PowerShell でそのまま動きます。
> Salesforce も「Salesforce CLI は Windows のコマンドプロンプトと PowerShell で最も良く動作する」
> としたうえで、WSL での利用を推奨していません。すでに WSL2 で開発されている方は、
> 構成が変わるため DigiMan 担当にご相談ください。

## 1. 準備する

### 1-1. zip を解凍する

**置き場所に注意してください。** `ドキュメント` フォルダの中は避けてください。
OneDrive の同期対象になっていると、うまく動かないことがあります。

おすすめは、ユーザーフォルダの直下です（例: `C:\Users\<あなたの名前>\digiman-onboarding`）。

エクスプローラーの「すべて展開」でも解凍できますが、確実なのは PowerShell です。
手順 1-2 でターミナルを開いてから、次を実行してください（パスはご自身のものに置き換えます）。

```powershell
Expand-Archive -Path "$Env:USERPROFILE\Downloads\digiman-sf-onboarding-codex-windows.zip" -DestinationPath "$Env:USERPROFILE"
```

### 1-2. ターミナルを開く

スタートメニューで「**ターミナル**」または「**PowerShell**」と入力して開きます。
どちらでも構いません。見つからない場合は Microsoft Store から Windows Terminal を入れてください。

以降のコマンドは、この画面に貼り付けて Enter を押します。

### 1-3. フォルダの中に移動する

`cd ` と打って、最後に**半角スペースを 1 つ**入れます。
そのまま、解凍したフォルダをエクスプローラーからターミナルの画面へ**ドラッグ＆ドロップ**して、
Enter を押します。

こうするとフォルダ名を打たずに移動できます。

### 1-4. 中身が揃っているか確認する

移動できたら、次を貼り付けて Enter。

```powershell
Get-ChildItem -Force
```

`AGENTS.md` `README.md` `.codex` `.agents` の 4 つが表示されれば正常です。

`.codex` と `.agents` は「.」で始まりますが、Windows では隠しフォルダ扱いにはならないため、
エクスプローラーでもそのまま見えます。見当たらない場合は解凍からやり直してください。

**フォルダを移動するときは、中身を選んでコピーせず、フォルダごと移動してください。**

## 2. Codex を入れる

すでに入っている場合はこの手順を飛ばして、手順 3 に進んでください。

**複数の方法を混ぜないでください。** 混ぜると、どちらが動くかが環境によって変わってしまいます。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

npm を使い慣れている場合は `npm install -g @openai/codex` でも構いません。どちらか 1 つだけです。

### PowerShell を開き直す

**インストールが終わったら、PowerShell をすべて閉じて開き直してください。**
新しいウィンドウでないと、インストールした場所が反映されません。
インストーラ自身も最後にそう案内します。

開き直したら、手順 1-3 のフォルダ移動をもう一度行ってから、次で確認します。

```powershell
Get-Command codex -ErrorAction SilentlyContinue
```

パスが 1 行表示されれば成功です。
何も表示されない場合は、もう一度ウィンドウを開き直してから試してください。
それでも出ない場合は DigiMan 担当にご連絡ください。

> インストーラは、コマンドの置き場所（`%LOCALAPPDATA%\Programs\OpenAI\Codex\bin`）を
> 自動で PATH に追加します。手動で設定する必要はありません。

## 3. このフォルダで Codex を起動する

**必ずこのフォルダの中で起動してください。**
フォルダの外から起動すると、このフォルダの指示は一切読み込まれません。
しかもエラーは出ず、ただの汎用エージェントとして普通に応答するため、失敗に気づけません。

手順 1-3 でフォルダの中にいる状態のまま、次を実行します。

```powershell
codex
```

フォルダを移動せずに起動したい場合は、`codex -C ` と打って半角スペースを入れ、
フォルダをエクスプローラーからドラッグ＆ドロップして Enter でも構いません。

`codex フォルダ名` のようにパスをそのまま書くと、フォルダ指定ではなく
「エージェントへの指示文」として解釈されるので注意してください。

## 4. 初回の確認に答える

初回起動時は、数ステップの初期設定があります。その中で次の 2 つが行われます。

- **サインイン**: `Sign in with ChatGPT` を選ぶとブラウザが開きます
- **フォルダの信頼確認**: `Do you trust the contents of this directory?` と表示されたら
  `Yes, continue` を選びます

信頼確認の選択肢は `Yes, continue` と `No, quit` の 2 つだけで、
信頼しない場合は Codex がそのまま終了します。
また、信頼しないと `.codex\config.toml`（このフォルダの推奨設定）が読み込まれません。

## 5. 最初の一文を送る

Codex は起動しただけでは何も話しません。入力欄に次を送ってください。

```text
Salesforce CLI が使えるか確認して
```

これを送ると、エージェントが自己紹介をして、`sf` が導入済みかどうかを確認し、
次に何を依頼すればよいかを 1 つ教えてくれます。

そのあとは、次のような文をそのまま送れます。

- 導入を進めたいとき
```text
Salesforce CLI をインストールして
```
- 良い使い方を相談したいとき
```text
Salesforce CLI で業務効率化する使い方を教えて
```
- 詳しく相談したいとき
```text
salesforce cliを使えるエージェントをつかってどうすれば業務効率化できると思うか？良い使い方を教えて
```

## 6. インストール時に確認が出ます

Codex は既定で、次の 2 つにあなたの承認を求めます。

- このフォルダの外への書き込み
- ネットワークを使うコマンドの実行

Salesforce CLI のインストールはこの両方に当たるため、途中で許可を求める表示が出ます。
**これは正常な動作です。** 内容を確認して許可してください。

環境によっては、一度エラーになってから許可を求める表示が出ることがあります。
その場合も、許可すればそのまま続きます。

### 何度も聞かれるのが煩わしい場合

このフォルダの `.codex\config.toml` の末尾に、ネットワークだけを許可する設定を
コメントとして用意してあります。行頭の `#` を消して保存し、Codex を起動し直してください。
**このフォルダのエージェントだけ**が対象です。

`/permissions` というコマンドでも権限を変えられますが、
**どれを選ぶかは DigiMan 担当に確認してください。一番強い設定は選ばないでください。**
サンドボックス（安全装置）を丸ごと外してしまう選択肢が含まれています。

## 7. Windows でつまずきやすいところ

### `.ps1 cannot be loaded because running scripts is disabled`

PowerShell の「実行ポリシー」が既定のままだと出ます。
この手順では Salesforce CLI をインストーラで入れるため通常は起きませんが、
npm で入れた場合に出ることがあります。

まず現状を確認します。

```powershell
Get-ExecutionPolicy -List
```

変更する場合は、管理者権限が不要なこちらを使ってください。

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

会社のポリシーで変更できないこともあります。その場合は DigiMan 担当にご連絡ください。

### コマンドを入れたのに「見つかりません」と出る

ほとんどの場合、**PowerShell を開き直していない**のが原因です。
すべて閉じて開き直し、フォルダに移動し直してから試してください。

### サンドボックスの設定で止まる

Codex の安全装置（サンドボックス）には強弱 2 つのモードがあり、
強いほうは管理者の承認を伴う初期設定が必要です。
会社支給 PC ではポリシーで止められることがあります。

その場合、Codex 自身が `/setup-default-sandbox` を案内するか、
自動的に弱いほうのモードに切り替わります。どちらも画面の案内に従ってください。
特定のフォルダが読めずに止まる場合は `/sandbox-add-read-dir C:\絶対パス` を使います。

> 不具合を調べるとき、`.sandbox-secrets` というフォルダの中身は
> **絶対に他の人に送らないでください。** 認証に関わる情報が入っています。

## 8. フォルダの構成

```
digiman-sf-onboarding-codex-windows\
├─ AGENTS.md                  このフォルダの正の指示（Codex はこれを読む）
├─ README.md                  このファイル
├─ .codex\
│  └─ config.toml             このフォルダでの推奨設定
└─ .agents\skills\
   └─ salesforce-cli-install\
      └─ SKILL.md             インストールを依頼されたときの手順
```

`AGENTS.md` が正の指示です。振る舞いを変えたいときはここを編集してください。
エージェント自身に「いまの指示を AGENTS.md に追記して」と頼むこともできます。

> **編集した内容は、いま動いているセッションには反映されません。**
> `AGENTS.md` と `.codex\config.toml` は、どちらも Codex の起動時に一度だけ読み込まれます。
> 編集したら Codex を一度終了して、起動し直してください。

## 補足: Codex が読む指示ファイルについて

このフォルダの指示は `AGENTS.md` に書かれています。
`CLAUDE.md` は Codex の公式ドキュメントに記載がなく、既定では読み込まれません。

なお Codex は `%USERPROFILE%\.codex\AGENTS.md`（全プロジェクト共通の個人設定）も読み込み、
このフォルダの `AGENTS.md` と連結します。
挙動がおかしいときは、そちらに矛盾する指示が入っていないかも確認してください。

macOS でお使いの場合は、mac 版のフォルダを別途ご用意しています。
